# Snatch CV | 측면 스내치 영상의 원판 궤적과 자세 분석

**바벨이 무릎을 지난 뒤 몸에 닿을 때까지 원판은 얼마나 올라갔을까?** 근대5종 국가대표팀 트레이너 경험에서 출발한 개인 프로젝트. 측면 MP4 한 편에서 카메라에 가까운 원판과 선수의 어깨·골반·무릎·발목을 추적하고, 트레이너가 원본 동작과 측정값을 대조할 수 있는 오버레이 영상·프레임별 CSV·구간 요약을 제공.

검증 선수 6명에서 베이스라인 대비 **동작 중 미탐 13→5장**, **최장 연속 좌표 누락 13→3프레임**, **구간 상승량 평균 절대오차 6.21→2.23 px**. 배포용 RTX 3090 TensorRT FP16에서는 **미탐 5장·오탐 0장, 상승량 오차 2.35 px** 확인. [실제 프레임에서의 엔진별 검증](docs/plate_aux_precision.md)

### 원판이 랙에 가려진 순간

검증 선수 a03의 같은 시도에서 2~14번을 프레임 순서대로 비교. 각 열은 같은 판정이 이어진 구간이며, **복구**는 수동 원판 박스와 IoU 0.50 이상으로 일치한 경우.

| 원본 프레임 번호 | 2–3 | 4 | 5–6 | 7–9 | 10–14 |
| --- | --- | --- | --- | --- | --- |
| 베이스라인 + 시간 연결 | 미탐 | 미탐 | 미탐 | 미탐 | 미탐 |
| CutMix 자동 보완 추가 | 미탐 | **직접 복구** | **시간 연결로 복구** | 미탐 | **직접 복구** |

**한 선수의 13프레임 중 8장 복구.** 보조 모델이 6장을 직접 검출하고 2장은 직전 궤적에 연결해, 가장 오래 비는 구간이 13프레임에서 3프레임으로 감소. 같은 영상 전체(122프레임)를 오버레이로 저장하는 데 걸린 시간은 Mac MPS에서 6.23초→8.48초(각 4회 중앙값). [프레임별 검증](docs/plate_cutmix_fallback.md) · [처리 시간 비교](docs/plate_fallback_timing.md)

**직접 수행한 작업** · 원판·동작 시점 라벨 작성, 허브·가까운 관절 수동 판독, 선수별 검증 설계, 모델 학습·시간 연결 구현, FastAPI·Docker·TensorRT 배포 검증.

## 영상 한 편 분석하기

가장 짧은 실행 경로는 Docker Compose의 CPU 서비스. 준비물은 Docker Compose, 측면 MP4, 로컬 모델 가중치. 선수의 발끝·손끝과 가까운 원판 테두리가 피니시까지 화면 안에 들어오도록 고정 촬영. 화면 경계에서 잘린 원판의 박스 중심은 실제 허브 위치와 달라질 수 있음.

1. 저장소 루트의 `models/pytorch/`에 아래 이름으로 가중치를 준비. 선수 영상·학습 가중치는 Git 배포 대상에서 제외. 원판 모델은 이 프로젝트에서 학습한 체크포인트가 필요하며, 원본 실험 폴더와 배포 파일명의 대응은 [모델 준비 안내](docs/analyze_mp4.md) 참고.

   | 파일명 | 쓰임 |
   | --- | --- |
   | `plate_baseline.pt` | 원판 직접 검출과 시간 연결 |
   | `plate_cutmix.pt` | 기본 추적이 빈 프레임 보완 |
   | `yolo26n-pose.pt` | 원본 YOLO26n-pose로 가까운 쪽 관절 추정 |
   | `plate_cosine.pt` (선택) | 무릎 통과와 바 접촉을 모두 지정한 경우의 상승량 측정 |

2. 서버를 시작하고 [로컬 API 문서](http://127.0.0.1:8001/docs)에서 `POST /analyses` 실행. 터미널에서는 아래 예시의 MP4 경로와 촬영 방향을 실제 영상에 맞게 변경.

   ```sh
   docker compose up --build -d api
   curl --fail-with-body http://127.0.0.1:8001/analyses \
     -F 'video=@./my-lift.mp4' -F near_side=left -F facing=right
   ```

   `near_side`는 카메라에 가까운 **선수 자신의 왼쪽·오른쪽**, `facing`은 선수가 바라보는 **화면의 왼쪽·오른쪽**. 두 값은 각각 `left` 또는 `right`. 동작 시점은 선택 입력이며 첫 프레임 번호는 0.

3. HTTP 201 응답의 `summary_url`, `files` 경로를 같은 서버에서 열어 결과 확인. 오버레이에서 원판·가까운 관절을 보고, CSV에서 같은 프레임의 직접 검출·시간 연결·미탐, 선택 모델과 좌표를 대조. 캐치와 피니시는 `recovery_review_url`에서 나중에 선택해 어깨 기준 원판의 앞뒤 거리와 체간 기울기 그래프 생성 가능. 기본 결과 폴더는 `outputs/docker_analysis/api/`. 서버 종료는 `docker compose down`.

Mac에서 Docker 없이 실행하는 방법은 [FastAPI](docs/fastapi.md)와 [파일 경로 CLI](docs/analyze_mp4.md) 참고. **API는 CutMix 자동 보완이 기본**, CLI는 단독 모델이 기본이며 `--plate-mode cutmix`로 동일한 보완 방식 선택 가능.

## 최종 모델을 선택한 근거

학습은 **8명·45장**, 검증은 다른 **6명·39장**으로 선수 단위 분리. 원본 검증 영상에서는 수동 박스가 있는 동작 중 **270장**에서 IoU ≥ 0.50으로 미탐·오탐을 채점하고, 전체 동작 **478프레임**에서 연속 좌표 누락을 집계. 상승량은 선수별 무릎 통과→바 접촉 한 구간씩 **총 6구간**에서 직접 찍은 원판 허브와 비교.

| 원판 모델 구성 · Mac FP32 | 동작 중 미탐 / 오탐 | 최장 좌표 누락 | 상승량 평균 절대오차 |
| --- | ---: | ---: | ---: |
| YOLO26n 베이스라인 + 시간 연결 | 13 / 0장 | 13프레임 | 6.21 px |
| 베이스라인 + CutMix 보완 | 5 / 0장 | 3프레임 | 6.21 px |
| 코사인 학습률 모델 단독 + 시간 연결 | 15 / 0장 | 12프레임 | 2.47 px |
| **채택 · CutMix 보완 + 두 시점에서만 코사인** | **5 / 0장** | **3프레임** | **2.23 px** |

- **추적.** 200에폭 상한에서 사진 mAP50–95는 **0.9256→0.9484**로 상승했지만, 같은 신뢰도 0.10에서 시간 연결 전 직접 미탐도 **16→32장**으로 증가. 100에폭 실행의 `best.pt`를 유지하고, 직접 검출과 직전 궤적 연결이 모두 빈 프레임에서만 CutMix의 추적 결과를 채택. 랙에 원판이 가려진 a03에서 기존 정탐을 유지하며 **8장 복구**. [실패 프레임 분석](docs/experiment-evidence.md) · [보조 모델 비교](docs/plate_cutmix_fallback.md)
- **상승량.** b02의 수동 허브 상승량 **326 px**에 대해 베이스라인 **305.80 px**, 코사인 모델 **324.29 px**. 코사인 모델이 중간 프레임을 놓친 점을 고려해, 무릎 통과·접촉 양 끝에서 기존 추적 박스와 일치할 때만 측정에 사용. [선수별 비교와 선택 기준](docs/plate_cosine_fallback.md)
- **자세.** 시험 파인튜닝 후 같은 검증 5장에서 수동점과의 평균 거리가 무릎 **17.99→28.30 px**, 발목 **26.30→33.10 px**로 증가해 원본 YOLO26n-pose 채택. 옷에 가려 추정한 골반은 주 각도 평가에서 제외. [관절점 비교 노트북](notebooks/experiments/30_pose_first_finetune.ipynb)

## 해석 범위

같은 시도에서의 **구간 이동량(px)과 평균 속도(px/s)**를 판독하는 도구. b02의 인접 두 구간은 프레임 간 이동량을 각각 **21.10 px 작게**, **18.05 px 크게** 측정해 구간 전체에서는 오차가 일부 상쇄됨. 촬영 거리와 배율이 다른 선수 간 절대 속도, 가려진 관절의 정확한 위치, 한 프레임의 순간 속도는 추가 검증이 필요한 항목. 검증 6명은 모델 선택에 반복 사용했고 실제 가림 복구 8장은 한 선수에게서 관찰. [수동 허브 대조와 한계](docs/experiment-evidence.md)
