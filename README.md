# Snatch CV | 측면 스내치 영상의 원판 궤적과 자세 분석

**바가 무릎을 지난 뒤 얼마나 빨라지고, 그때까지 몸통은 얼마나 세워졌을까?** 근대5종 국가대표팀 트레이너로 일하며 관찰한 동작을 측면 MP4 한 편에서 다시 살펴보기 위한 개인 프로젝트. 랙이 원판을 가리면 궤적이 끊기고, 원판 일부만 검출하면 박스 중심과 실제 중심(허브)이 어긋나는 문제에서 출발.

검증 사진 점수가 올라도 영상에서 원판을 더 자주 놓친 200에폭 모델은 보류. **100에폭 YOLO26n**으로 추적하고 빈 프레임만 CutMix 모델로 채워 검증 6명의 **동작 중 미탐 13→5장, 오탐 0장 유지**. 무릎 통과와 바 접촉 두 시점에만 코사인 학습률 모델을 적용해 **상승량 평균 절대오차 6.21→2.23 px**(Mac FP32). [모델 조합별 결과](docs/plate_cosine_fallback.md)

**직접 수행한 범위** · 원판·관절 라벨링 → 모델 학습과 선수별 검증 → 원판 추적·자세 측정 → FastAPI·Docker·RTX 3090 배포 검증.

## 영상 한 편에서 확인하는 결과

MP4와 촬영 방향을 입력하면 **원판 궤적과 가까운 쪽 관절을 겹친 영상**, **프레임별 좌표·검출 출처 CSV**를 생성. 이륙·무릎 통과·바 접촉 시점을 지정하면 Swagger에서 아래 수치까지 확인 가능.

| 실제 검증 영상 한 편 · Mac API 응답 | 측정값 |
| --- | ---: |
| 이륙 → 무릎 통과 · 원판 평균 수직속도 | **300.96 px/s** |
| 이륙 → 무릎 통과 · 체간 기울기 변화 | **−10.66°** (몸통이 수직에 가까워짐) |
| 무릎 통과 → 바 접촉 · 원판 평균 수직속도 | **403.93 px/s** |
| 앞/뒤 평균속도 비율 | **0.745** |

무릎 통과 후 속도는 두 끝점에서 채택한 상승량을 원본 경과 시간으로 나눠 계산. 검증 6명의 수동 허브를 기준으로 후반 평균속도의 평균 절대오차 **22.42 → 7.90 px/s**(Mac CPU). [Swagger 요청·응답](docs/fastapi.md#swagger에서-속도와-체간-기울기-읽기)

## 최종 모델을 선택한 근거

원판 검출 학습 **8명·45장**, 사진 검증 **다른 6명·39장**으로 분리. 같은 검증 선수의 원본 영상에서 동작 중 수동 박스 **270장**으로 미탐·오탐을 채점하고, **478프레임**으로 연속 좌표 누락을 확인. 상승량은 선수당 한 구간씩 **6구간**에서 직접 찍은 허브와 대조.

| 선택 | 결정을 바꾼 실험 결과 |
| --- | --- |
| **원판 주 추적기 · 100에폭 YOLO26n 유지** | 학습 상한을 200에폭으로 늘리자 사진 검출 점수(mAP50–95)는 0.9256→0.9484로 상승. 같은 신뢰도 기준 0.10에서 시간 연결 전 **동작 중 직접 미탐은 16→32장**으로 증가. [학습 일정 비교](docs/experiment-evidence.md#원판-학습-일정과-검출-신뢰도) |
| **가림 복구 · CutMix 학습 모델로 빈 프레임만 보완** | 부분 원판을 학습한 모델이 랙 뒤 원판을 찾았지만 다른 장면에서는 기존 정탐을 놓침. 주 모델의 직접 검출·시간 연결이 모두 빈 경우에만 적용해 한 선수의 **13프레임 중 8장 복구**, 최장 연속 누락 **13→3프레임**. [프레임별 비교](docs/plate_cutmix_fallback.md) |
| **상승량 · 두 시점에서만 코사인 학습률 모델 사용** | 수동 상승량 326 px인 장면에서 기본 모델은 305.80 px, 학습률 0.0005·코사인 감소 모델은 **324.29 px**로 측정. 중간 프레임을 놓친 사례가 있어 무릎 통과·접촉 양쪽에서 기존 추적 박스와 겹칠 때만 상승량에 사용. [채택 기준](docs/plate_cosine_fallback.md) |
| **자세 · 원본 YOLO26n-pose 유지** | 파인튜닝 후 검증 5장에서 수동점과의 평균 거리가 무릎 **17.99→28.30 px**, 발목 **26.30→33.10 px**로 증가. 여러 사람이 보이면 카메라에 가장 가까운 수행자를 선택해 가까운 쪽 어깨·골반·무릎·발목을 추적. [관절점 비교](notebooks/experiments/30_pose_first_finetune.ipynb) · [수행자 선택 검증](docs/performer_continuity.md) |

FiftyOne에서 미탐 장면을 다시 열어 보니 정답과 잘 겹친 후보(IoU **0.908**)가 낮은 신뢰도(**0.141**) 때문에 탈락. 별도 가림 실험에서는 같은 31장에 붙인 패치를 원판 중앙에서 아래 테두리로 옮기자 정탐이 **26→22장**으로 감소. [FiftyOne 검수 노트북](notebooks/experiments/01_plate_baseline.ipynb) · [가림 위치 대조](notebooks/experiments/08_plate_patch_position.ipynb)

## 모델 선택에 쓰지 않은 선수에서의 최종 평가

배포 설정을 고정한 뒤 기존 영상에서 학습·검증과 겹치지 않는 **3명의 7편**을 후향 평가. 예측을 숨기고 영상마다 동작 구간의 다섯 시점에 원판 박스를 판독. Mac CPU에서 **35장 중 34장 정탐(재현율 97.1%), 미탐 1장·오탐 0장**. 동작 전체에서는 **434프레임 중 433프레임**에 좌표가 있었고 최장 공백은 **1프레임**. 판독한 35장에는 모두 원판이 있어 원판 없는 영상의 오탐률은 미측정. [선수별 결과와 7편의 판독 분포](docs/plate_holdout.md)

FiftyOne에서 미탐의 앞뒤 프레임을 비교하니 같은 선수의 상체와 전신에 사람 박스가 겹쳐, 올바른 원판 후보까지 보류된 사례 확인. 두 박스를 묶자 해당 장면은 복구됐지만 기존 검증 6명에서는 **미탐 5장·오탐 0장으로 동일**해 배포 규칙 유지. [후속 실험과 채택 판단](docs/plate_person_containment.md)

## RTX 3090 배포 검증

Netron으로 원판·자세 ONNX의 입출력 구조를 확인하고, PyTorch와 ONNX Runtime의 좌표를 같은 프레임에서 대조. GPU에서는 처리 시간과 실제 선수 영상의 측정 오차를 함께 보고 TensorRT FP16 채택. [원판 좌표 대조](docs/onnx_plate_parity.md) · [관절 좌표 대조](docs/onnx_pose_parity.md)

| 검증 범위 | 결과 |
| --- | --- |
| **처리 시간** · 같은 RTX 3090, 합성 116프레임, 원판·자세 두 모델, 각 2회 평균 | 모델 로드부터 오버레이·CSV 저장 후 종료까지 PyTorch CUDA FP32 **5.08초**, ONNX Runtime CUDA FP32 5.52초, TensorRT FP32 4.06초, **TensorRT FP16 3.79초**. [실측 조건](docs/tensorrt_3090.md) |
| **실제 영상 품질** · 검증 6명, 수동 박스 270장과 상승량 6구간 | 최종 구성의 FP16에서도 **미탐 5장·오탐 0장** 유지. 상승량 평균 절대오차는 Mac FP32 **2.23 px**, RTX 3090 FP16 **2.35 px**. [엔진별 대조](docs/plate_aux_precision.md) |
| **배포 경로** · 저장소 GPU Dockerfile로 만든 이미지에 합성 MP4 제출 | FastAPI **HTTP 201**. 내려받은 H.264 오버레이 **24프레임** 전체 디코딩, 기준과 바이트가 같은 **CSV 24행** 확인. [GPU 컨테이너 검증](docs/gpu_fastapi.md#저장소-dockerfile로-빌드한-이미지-검증) · [CPU Docker 재현](docs/cpu_docker.md) |

**해석 범위.** 한 시도에서 프레임 간 상승량을 연달아 **21.10 px 작게**, **18.05 px 크게** 측정한 사례가 있어 코칭에서는 구간 평균 속도와 상승량까지 해석. 옷에 가린 골반 등 추정한 점은 주 각도 평가에서 제외. 실제 가림 복구는 검증 선수 한 명에서 관찰. 다른 촬영 환경과 두 수행자가 실제로 겹치는 장면에서의 재현성은 후속 검증 과제. [수동 측정과 한계](docs/experiment-evidence.md#실험별-질문과-판단)

## 영상 한 편 분석하기

**로컬 실행 준비물**은 Docker Compose, 측면 MP4, 모델 가중치. 선수 영상과 가중치는 별도 보관하므로 공개 저장소만 내려받은 상태에서는 위 실측 결과와 검증 기록을 확인할 수 있음. 실행하려면 선수와 원판 테두리가 끝까지 보이는 고정 촬영 영상과 아래 모델 준비.

1. `models/pytorch/`에 직접 학습한 `plate_baseline.pt`, `plate_cutmix.pt`와 원본 `yolo26n-pose.pt` 배치. `plate_cosine.pt`는 선택이며 생략하면 기존 추적 좌표로 상승량 계산. [모델 파일 준비](docs/analyze_mp4.md#실행-코드와-배포-모델)
2. 저장소 루트에서 CPU 서버 실행.

   ```sh
   docker compose up --build -d api
   ```

3. [로컬 Swagger](http://127.0.0.1:8001/docs)에서 **POST /analyses → Try it out** 선택. MP4와 카메라에 가까운 **선수 자신의 좌우**(`near_side`), 선수가 보는 **화면의 좌우**(`facing`) 입력. 동작 시점은 선택 사항이며 첫 프레임은 0번.
4. **Execute** 후 응답의 `files`에서 영상·CSV 확인. 캐치·피니시는 `recovery_review_url`에서 사후 선택해 어깨 기준 원판 위치와 체간 기울기 그래프 생성 가능. 기본 저장 위치는 `outputs/docker_analysis/api/`, 종료 명령은 `docker compose down`.

### Mac에서 측면 영상 한 편 분석하기
