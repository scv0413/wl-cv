# Snatch CV | 측면 스내치 영상의 원판 궤적과 자세 분석

**원판이 무릎을 지난 뒤 얼마나 빨라지고, 무릎을 지날 때까지 몸통은 얼마나 세워질까?** 근대5종 국가대표팀 현장 경험에서 출발한 개인 프로젝트. 측면 MP4 한 편에서 원판의 수직 이동과 수행자의 자세를 측정하고, 직접 표시한 원판 중심(허브)과 관절점을 기준으로 모델 선택.

| 분석 | 배포 모델을 선택한 이유 |
| --- | --- |
| **Object Detection · 원판 검출** | 100에폭 YOLO26n으로 원판을 추적하고, 시간 연결 후에도 좌표가 비면 CutMix 모델로 보완. 검증 선수 6명의 동작 중 **미탐 13→5장, 오탐 0장 유지**. |
| **Pose Estimation · 자세 추정** | 원본 YOLO26n-pose로 카메라에 가까운 어깨·골반·무릎·발목 추정. 파인튜닝 후 같은 검증 5장에서 무릎과 발목의 위치 오차가 모두 커져 원본 모델 채택. |

## Object Detection · 랙에 가려진 원판의 궤적 복구

랙 뒤에서 원판을 연속으로 놓치고, 일부만 검출한 장면에서는 박스 중심이 실제 허브와 어긋남. FiftyOne에서 미탐을 열어 보니 정답 박스와 잘 겹친 후보(IoU **0.908**)도 신뢰도 **0.141**로 기준 0.25에 미달. 질감 가림을 학습한 모델에서는 같은 패치를 원판 중앙에서 아래 테두리로 옮기자 5명 31장의 정탐이 **26→22장**으로 감소. [FiftyOne 검수](notebooks/experiments/01_plate_baseline.ipynb) · [가림 위치 대조](notebooks/experiments/08_plate_patch_position.ipynb)

학습 8명·45장과 검증 6명·39장을 선수별로 분리. 같은 검증 6명의 영상에서 동작 중 수동 박스 **270장**으로 미탐·오탐을, **478프레임**으로 연속 좌표 누락을 평가.

| 비교 | 관찰과 선택 |
| --- | --- |
| 100에폭과 200에폭 상한 | 학습 상한을 늘리자 검증 사진의 mAP50–95는 0.9256→0.9484로 상승. 같은 신뢰도 기준 0.10에서 동작 중 직접 미탐은 **16→32장**으로 증가해 100에폭 실행의 최적 가중치 유지. [학습 일정 비교](docs/experiment-evidence.md#원판-학습-일정과-검출-신뢰도) |
| CutMix 단독과 보조 사용 | 같은 RTX 3090의 대조군과 비교하면 CutMix가 동작 중 **9장을 복구**했지만 기존 정탐 **4장을 새로 놓침**. 주 모델의 직접 검출과 시간 연결이 모두 빈 장면만 보완하자 랙이 겹친 한 시도에서 **8장 복구**, 최장 연속 누락 **13→3프레임**. [단독 모델 대조](docs/plate_cutmix.md) · [보조 모델 평가](docs/plate_cutmix_fallback.md) |
| 이전 무릎 통과→접촉 상승량 실험 | 학습률 0.0005·코사인 감소 모델이 중간 장면을 놓쳐 궤적은 기존 모델로 유지. 무릎 통과와 바 접촉을 지정하고 양 끝의 박스가 기존 추적과 각각 IoU 0.50 이상일 때만 코사인 모델로 상승량 계산. 선수당 한 구간씩 6구간에서 수동 허브 대비 평균 절대오차 **6.21→2.23 px**. [두 시점의 상승량 비교](docs/plate_cosine_fallback.md) |

**모델 선택에 쓰지 않은 선수에서의 평가.** 배포 설정을 고정하고 3명·7편에서 예측을 숨긴 채 영상당 다섯 장면을 판독. 원판이 보이는 **35장 중 34장 정탐(재현율 97.1%), 미탐 1장·오탐 0장**. 전체 동작에서는 434프레임 중 433프레임에 좌표 기록. 미탐 장면에서는 같은 수행자의 상체·전신 박스가 겹쳐 원판 후보까지 보류됨. 상체와 전신 박스를 같은 수행자로 묶자 해당 장면은 복구됐지만 기존 검증 6명의 결과가 같아 배포 규칙 유지. 원판이 없는 새 영상의 오탐률은 미측정. [선수별 후향 평가](docs/plate_holdout.md) · [수행자 박스 대조](docs/plate_person_containment.md)

## Pose Estimation · 가려진 관절의 위치 오차 확인

측면에서는 바벨에 어깨가 가려지고 옷 아래 골반 위치를 추정해야 하는 장면이 발생. 여러 사람이 보이면 카메라에 가장 가까운 수행자를 선택하고, 가까운 쪽 관절만 분석. 원본에서 직접 확인한 점, 위치를 추정한 점, 판독 불가를 구분해 기록하고 직접 확인한 점으로 위치 오차를 평가. [수행자 선택 검증](docs/performer_continuity.md) · [관절 판독 기준](docs/experiment-evidence.md#실험별-질문과-판단)

사람별 분할을 유지해 5장으로 파인튜닝한 뒤, 다른 선수의 동일한 검증 5장에서 수동점과 예측점 사이의 평균 거리를 비교. 수행자 미탐은 두 모델 모두 **0/5장**이었지만, 무릎 오차는 **17.99→28.30 px**, 발목은 **26.30→33.10 px**로 증가. 이 비교를 근거로 **원본 YOLO26n-pose** 채택. [원본·파인튜닝 관절점 비교](notebooks/experiments/30_pose_first_finetune.ipynb)

## 수치 계산 · 구간 평균 수직속도와 체간 기울기

원판 중심이 올라간 거리(px)를 원본 영상의 경과 시간(s)으로 나눠 같은 시도의 구간 평균속도를 계산. 한 시도에서 연속한 두 프레임 간격의 상승량을 각각 **21.10 px 작게**, **18.05 px 크게** 측정한 사례가 있어 구간 평균을 사용. 체간 기울기는 가까운 쪽 어깨와 골반을 이은 선과 화면 수직선 사이의 각도로 계산. [수동 허브·관절점과의 대조](docs/experiment-evidence.md#실험별-질문과-판단)

| 측정 항목 | 측면 영상 한 편에서 두 시점을 수동 확인한 결과 |
| --- | ---: |
| 원판 상승 시작(`ready`) → 가까운 무릎 높이 통과(`transition`) 평균 수직속도 | **300.96 px/s** |
| 같은 구간의 체간 기울기 변화 | **10.66° 더 세워짐** |
| 무릎 통과 → 첫 상승 최고점 평균 수직속도 | **621.00 px/s** |
| 뒤/앞 속도 비율 = 후반 평균속도 ÷ 전반 평균속도 | **2.06배** |

무릎 통과 이후 원판이 두 번 이상 연속 상승하고 세 프레임 연속 하강하기 직전의 위치를 첫 최고점으로 확인. 최고점을 확인하기 전에 영상이 끝나거나 원판이 잘리거나 좌표가 끊기면 후반 속도와 비율은 산출 보류. 두 구간의 평균속도와 비율은 바 접촉·캐치 입력 없이 계산. [수치 정의와 응답 필드](docs/fastapi.md#swagger에서-속도와-체간-기울기-읽기)

## FastAPI · 영상 분석과 시점 수정

`POST /analyses`에 MP4와 촬영 방향을 보내면 원판 궤적·관절을 겹친 영상과 프레임별 좌표·검출 출처 CSV를 생성. `ready`와 `transition`을 비우면 두 시점을 자동 제안. 검수 화면에서 시점을 수정하면 저장된 궤적으로 평균속도와 비율을 다시 계산. 위 시도에서는 **자동 시점 1.35배 → 수동 확인 후 2.06배**로 달라졌고 첫 상승 최고점은 동일. [Swagger 요청·응답과 검수 화면](docs/fastapi.md#당기기-시점-제안과-검수)

기본 분석은 원판 베이스라인·CutMix와 원본 자세 모델로 실행. 116프레임 검증 영상 한 편에서 코사인 추론을 **113→0회**로 줄인 뒤에도 자동 후반 속도 **1,023.06 px/s**, 뒤/앞 비율 **1.447배**, 오버레이·프레임 CSV가 동일. [변경 전후 검증](docs/fastapi.md#기본-세-모델-검증)

## RTX 3090 · TensorRT FP16과 GPU Docker 배포 검증

Netron에서 두 모델의 ONNX 입출력 구조를 확인한 뒤 같은 프레임으로 PyTorch와 ONNX Runtime 출력을 대조. 원판 후보 3,220쌍의 박스 좌표 차이는 최대 **0.001221 px**, 가까운 쪽 관절의 표시·보류 판정은 **48/48 일치**. [원판 좌표](docs/onnx_plate_parity.md) · [관절 좌표](docs/onnx_pose_parity.md)

| 검증 범위 | 실측 결과 |
| --- | --- |
| **전체 처리 시간** · 합성 영상 116프레임, 원판·자세 두 모델, 같은 GPU에서 각 2회 평균 | 모델 로드부터 오버레이·CSV 저장 후 종료까지 PyTorch CUDA FP32 **5.08초**, ONNX Runtime CUDA FP32 5.52초, TensorRT FP32 4.06초, **TensorRT FP16 3.79초**. [측정 조건](docs/tensorrt_3090.md) |
| **변환 후 원판 품질** · 실제 검증 선수 6명, 수동 박스 270장과 무릎 통과→바 접촉 6구간 | FP16에서 **미탐 5장·오탐 0장** 유지. 수동 허브 대비 상승량 평균 절대오차는 PyTorch FP32 **2.23 px**, TensorRT FP16 **2.35 px**. [엔진별 대조](docs/plate_aux_precision.md) |
| **GPU 컨테이너의 요청부터 파일 다운로드까지** · 저장소 Dockerfile로 빌드한 이미지에 합성 MP4 제출 | 당시 코사인 포함 4엔진 구성에서 **HTTP 201**. 현재 기본 3엔진 구성의 GPU 시간은 미측정. 내려받은 H.264 오버레이 **24프레임** 전체 디코딩과 기준 파일과 동일한 **CSV 24행** 확인. [GPU 배포 검증](docs/gpu_fastapi.md#저장소-dockerfile로-빌드한-이미지-검증) · [CPU Docker 검증](docs/cpu_docker.md) |

## 영상 한 편 분석하기

**로컬 실행 준비물**은 Docker Compose, 측면 MP4, 모델 가중치. 선수 영상과 가중치는 별도 보관하므로 공개 저장소만 내려받은 상태에서는 위 실측 결과와 검증 기록을 확인할 수 있음. 실행하려면 선수와 원판 테두리가 끝까지 보이는 고정 촬영 영상과 아래 모델 준비.

1. `models/pytorch/`에 직접 학습한 `plate_baseline.pt`, `plate_cutmix.pt`와 원본 `yolo26n-pose.pt` 배치. 이전 무릎 통과→접촉 실험을 재현할 때만 `plate_cosine.pt` 추가. [모델 파일 준비](docs/analyze_mp4.md#실행-코드와-배포-모델)
2. 저장소 루트에서 CPU 서버 실행.

   ```sh
   docker compose up --build -d api
   ```

3. [로컬 Swagger](http://127.0.0.1:8001/docs)에서 **영상 분석 → MP4 한 편 분석 → Try it out** 선택. MP4와 카메라에 가까운 **선수 자신의 좌우**(`near_side`), 선수가 보는 **화면의 좌우**(`facing`) 입력. 시점을 비우면 `ready`·`transition`을 자동 제안. `pull_review_url`에서 장면을 확인하고 구간 평균속도와 뒤/앞 비율을 다시 계산.
4. **Execute** 후 응답의 `files`에서 영상·CSV 확인. 캐치·피니시는 `recovery_review_url`에서 사후 선택해 어깨 기준 원판 위치와 체간 기울기 그래프 생성 가능. 기본 저장 위치는 `outputs/docker_analysis/api/`, 종료 명령은 `docker compose down`.

### Docker 없이 실행하기

[개발 환경 준비](docs/fastapi.md#서버-시작) 후 프로젝트 루트의 가상환경에서 `fastapi dev` 실행. 브라우저에 [개발 서버 Swagger](http://127.0.0.1:8000/docs)가 열리며, **시점 검수**에서 기존 분석의 속도 재계산 또는 캐치·피니시 그래프 생성 가능. 터미널에서 영상 경로를 입력하는 방법은 [파일 경로 CLI](docs/analyze_mp4.md) 참고. API는 CutMix 자동 보완이 기본이며 CLI에서는 `--plate-mode cutmix`로 선택.
