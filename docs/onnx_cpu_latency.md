# 원판·자세 ONNX의 CPU 스레드 수와 프레임 지연

Mac M2에서 검증 영상 c04의 같은 116장을 4·2·6·6·2·4스레드 순서로 처리했다. 회차마다 첫 장으로 10회 예열하고 배치 1, 입력 640×384, FP32, 동일한 그래프와 공통 전처리를 사용했다. ORT의 연산 스레드 수만 바꿨다.

| 스레드 | 프레임 중앙값(ms) | p95(ms) |
| ---: | ---: | ---: |
| 2 | 70.51 | 74.17 |
| 4 | 48.74 | 60.13 |
| 6 | 49.08 | 58.45 |

4스레드에서 단계별 중앙값은 디코딩 3.26 ms, 전처리 0.84 ms, 원판 추론 19.43 ms, 자세 추론 24.00 ms, NMS와 좌표 복원 0.75 ms였다. 전체 지연은 프레임마다 직접 측정했다. 모델 초기화, 시간 연결, 오버레이·인코딩, 파일 저장은 측정에서 제외했다.

세 조건에서 프레임별 후보 수와 표시 기준 통과 여부가 같았다. NMS 후 4스레드와의 최대 좌표 차이는 0.000994 px, 점수 차이는 0.00000343이었다. 6스레드에서 중앙값 이득이 없고 회차별 p95도 변동해 기존 4스레드를 유지한다. 30 fps 원본의 프레임 간격 33.33 ms를 넘으므로 두 모델의 실행 장치를 다음 변수로 선택했다.
