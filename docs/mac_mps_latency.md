# Mac GPU에서 원판·자세 모델의 지연과 분석값 비교

검증 영상 c04의 원본 116장을 Apple M2에서 조건별로 두 번 처리했다. 같은 사전학습 자세 모델과 원판 베이스라인, 입력 FP32 640×384, 배치 1을 사용했다. PyTorch CPU와 MPS는 동일한 가중치를 사용했다. ONNX Runtime CPU 4스레드는 46·47번에서 검증한 그래프를 사용했다.

| 실행 경로 | 중앙값 (ms) | p95 (ms) | 33.33 ms 이내 |
| --- | ---: | ---: | ---: |
| PyTorch CPU | 69.72 | 81.95 | 0/232 |
| ONNX Runtime CPU | 46.95 | 49.82 | 0/232 |
| PyTorch MPS | 22.29 | 28.14 | 228/232 |

MPS의 두 실행에서 중앙값은 각각 22.38, 22.14 ms였다. 원본의 30 fps 간격은 약 33.33 ms다. 이 조건에서 MPS는 Mac의 추론 후보로 채택할 수 있다. 영상 한 편에서 측정한 디코딩~좌표 복원 지연이며, 완성된 오버레이 영상의 처리 속도는 별도 측정이 필요하다.

## 분석값이 유지됐나

- 세 조건 모두 원판을 116/116장에서 직접 선택했다. 이륙 11번에서 무릎 통과 27번까지 원판 중심의 상승량은 +160.51 px, 체간 기울기 변화는 −10.66°로 같았다.
- NMS 후 프레임별 원판·사람 후보 수와 직접 원판·관절 신뢰도 기준 통과 여부가 모든 조건에서 일치했다. PyTorch CPU와 MPS의 박스 축·관절 위치 차이 중 최댓값은 0.003681 px, 점수 차이는 최대 0.00000656이었다. 관절은 화면상 두 점 사이 거리로 쟀다.
- 디코딩, 공통 전처리, 두 모델의 추론, NMS·원본 좌표 복원을 포함했다. MPS 입력 이동, GPU 완료 대기와 CPU 출력 반환도 포함했다. 모델 로딩, 시간 연결·구간 집계, 오버레이, 인코딩, 파일 저장은 측정 밖이다. 후보 비교와 상승량·각도 계산은 시간 측정이 끝난 후에 수행했다.
- 회차 순서는 PyTorch CPU, PyTorch MPS, ONNX Runtime CPU, 그리고 역순이었다. 매 회차 첫 장으로 10회 예열했다. 공식 PyTorch CPU 경로와 같은 헤드를 사용하고 GPU 자동 CPU 폴백을 끈 상태로 노트북을 실행했다. FPS 기준을 통과한 228개는 같은 영상 프레임 116장을 두 번 측정한 결과다.
