# MPS 오버레이 영상 한 편의 전체 처리 시간

검증 영상 c04_sn_f_01을 Mac M2에서 새 프로세스로 한 번 분석했다. 3.867초짜리 영상(116프레임, 30 fps)의 H.264 오버레이와 CSV·JSON을 만드는 데 명령 시작부터 종료까지 **12.695초**가 걸렸다. 평균 처리 속도는 **9.14 fps**였고 소요 시간은 재생 길이의 3.28배였다. 분석 함수 안에서 가중치 로딩부터 영상·측정 결과 저장까지는 **10.191초(11.38 fps)**였다. 모델 입력은 기존 FP32, 긴 변 640, 배치 1이고 출력 영상은 원본 크기 1080×1920이다.

## 시간 측정 범위

별도로 예열하지 않고 기존 분석 명령의 두 번 읽는 구조를 유지했다. 아래는 한 번의 관측값이다.

| 분석 함수 안의 단계 | 경과 시간 |
| --- | ---: |
| 원판 모델 준비·첫 번째 영상 읽기·검출 | 5.223초 |
| 원판 궤적 선택·시간 연결 | 0.028초 |
| 두 번째 읽기 중 자세 예측 호출·CPU 결과 반환 | 3.328초 |
| 오버레이 그리기 | 0.210초 |
| 영상 프레임 쓰기·인코더 종료 대기 | 0.734초 |
| 두 번째 읽기·자세 모델 준비·프레임 기록 등 나머지 | 0.640초 |
| 메타데이터 설정·산출물 확인 및 저장 | 0.030초 |

분석 함수의 타이머는 결과 CSV와 요약 JSON을 쓰고 멈춘다. 명령 전체 시간에는 프로세스 시작·라이브러리 로딩·시간표 기록·결과 폴더 확정·프로세스 종료도 들어간다. 출력 영상을 다시 끝까지 디코딩한 사후 검수는 별도로 수행했다. 49번 실험의 22.29 ms는 예열된 두 모델이 프레임을 한 번 읽고 좌표로 복원할 때까지의 중앙값이다. 두 실험은 타이머 범위와 실행 경로가 다르므로 시간 차이를 인코딩 비용으로 계산할 수 없다.

## 분석 결과와 검수

- 완성된 H.264 파일을 OpenCV와 ffprobe로 읽어 1080×1920, 30 fps, 116프레임을 확인했다. 이륙 11번과 무릎 통과 27번에서 원판 박스·가까운 쪽 관절·동작 시점 표기가 보였고 마지막 115번까지 표시가 이어졌다.
- 원판 직접 검출 116장, 시간 연결 0장, 미탐 0장이었다. 11→27번 중심 상승량은 **+160.51 px**, 체간 기울기는 **58.12° → 47.46°(−10.66°)**였다. 49번 MPS 측정과 표시 정밀도에서 같았다. 기존 CPU 영상 분석 기록과도 모든 프레임의 원판 상태, 사람 수, 표시 관절 수, 수동 시점이 일치했다.
- 이 영상에서는 해상도를 먼저 낮출 근거가 부족하다. 다음 비교에서는 두 모델이 프레임을 한 번만 읽고 전처리를 공유하게 한 뒤, 같은 H.264 출력·구간 측정값을 유지하며 영상 생성 시간이 줄어드는지 측정한다.
