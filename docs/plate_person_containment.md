# 상체·전신 박스의 포함 관계로 원판을 복구할 수 있는가

후향 테스트 하프 영상의 54번에서 한 사람에게 상체 박스와 전신 박스가 동시에 생겼다. 수행자 선택이 보류되면서 정답과 겹친 원판도 최종 출력에서 빠졌다. 이 장면에서 얻은 가설을 기존 검증 6명의 원본 영상에서 비교했다.

## 비교 방법

- 대조군은 배포 리비전 `430ccb2`의 Mac CPU 입력 640, 베이스라인 + CutMix, 기존 수행자 선택과 시간 연결이다. 같은 원본에서 저장한 사람·원판 후보를 공유하고 각 조건은 영상 첫 프레임에서 빈 추적 이력으로 시작했다. 대조군의 수행자·원판 후보 목록·출력 모델·검출 상태·박스 좌표를 이전 배포 비교 기록과 프레임별로 대조했다.
- 실험군은 작은 박스가 더 짧고, 중심이 큰 박스의 위쪽 절반에 있으며, 작은 박스 면적의 90% 이상이 큰 박스와 겹치면 두 박스를 같은 수행자의 후보로 묶었다. ‘거의 다 들어간다’를 수치로 표현한 탐색 기준이다. 수행자를 이미 선택했으면 선택 박스와 직접 묶인 박스 주변의 원판도 허용했다. 선택을 보류했으면 모든 후보 쌍이 기존 IoU 0.50 기준이나 새 포함 조건 중 하나를 만족할 때만 원판을 허용했다. 원판 여유 15%와 시간 연결은 그대로 적용하고 자세는 기존 선택 상태를 따랐다.
- 동작 구간은 ready~finish(하프는 drive) 양 끝 포함이다. 수동 원판 박스가 있는 장면에서 IoU 0.50 이상을 정탐으로 셌다. 같은 선수의 연속 프레임은 독립된 시도로 보지 않았다.

## 검증 6명 결과

| 지표 | 기존 배포 | 포함 관계 추가 |
|---|---:|---:|
| 동작 중 정탐 / 수동 박스 270장 | 265 | 265 |
| 동작 중 미탐 / 오탐 | 5 / 0 | 5 / 0 |
| 동작 중 좌표 누락 / 478프레임 | 5 | 5 |
| 동작 중 최장 연속 누락 | 3프레임 | 3프레임 |

전체 687프레임 중 16장에서 한 쌍씩 묶였다(동작 전 2, 동작 중 11, 동작 후 3). 그중 b02 34번, b03 17번, c08 20·21번에서 필터를 통과한 원판 후보 목록이 달라졌다. 최종 원판이 달라진 프레임, 새로 복구한 정탐, 잃은 정탐은 모두 0장이었다. 미탐 5장은 모두 a03 2·3·7·8·9번으로, 프레임마다 사람 후보가 하나라서 이 규칙이 관여할 수 없었다.

묶인 16장의 원본을 박스와 대조했다. 서로 다른 두 수행자를 묶은 것으로 보이는 장면은 0장이었다. 16장은 선수 5명의 장면이고 동작 중 11장에는 기존 수행자 참고 박스도 있다. 동작 전·후 5장은 원본 육안 판독이다. 두 선수가 실제로 겹쳤다는 신원 정답을 갖춘 사례군은 없어, 이런 촬영에서의 오연결률은 측정하지 못했다. 선수와 판독 근거는 [원본 대조표](../data/annotations/performer_containment_review.csv)에 남겼다.

## 54번 재현과 판단

가설이 나온 a07 영상은 검증 6명의 집계에서 제외했다. 원본을 첫 장부터 다시 처리하니 기존 방식은 54번을 보류했고, 새 방식은 베이스라인 원판을 직접 검출했다(신뢰도 0.962, 수동 박스 IoU 0.933). 두 경우 모두 자세는 보류했고 53·55번 원판 좌표는 같았다. 이 한 장은 규칙이 의도대로 작동한다는 확인에 썼다. 검증 6명에서 원판 개선이 없고 혼잡한 장면의 오연결 위험도 충분히 측정하지 못해 배포 설정을 유지한다.
