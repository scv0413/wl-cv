# 스내치 측면 영상에서 원판과 자세를 어디까지 측정했는가

측면 영상 한 편을 넣으면 원본과 같은 프레임 번호로 원판·자세 오버레이, 검출 상태와 관절 좌표 CSV, 구간 수치 JSON이 나온다. 가까운 원판과 관절만 다룬다. 아래 초기 실험은 사람이 판독한 동작 시점을 사용했다. 현재 FastAPI는 ready·transition을 자동 제안하고, 원판 궤적의 첫 상승 최고점까지 후반 평균속도를 계산한다.

원판 검출기와 자세 모델의 변환 전후 품질, 오버레이 저장 시간, 입력 640을 선택한 이유는 [실행 엔진과 영상 처리의 트레이드오프](runtime_quality_tradeoff.md)에 정리했다.

## 포트폴리오에서 먼저 보여줄 내용

> 근대5종 국가대표팀 현장에서 스내치의 어느 구간에서 바가 빨라지는지에 주목했다. 측면 영상 한 편에서 원판을 추적하고 가까운 쪽 관절을 표시하는 도구를 만들고, 코칭에 쓸 수 있는 측정 범위를 직접 찍은 허브와 관절점으로 확인했다.

**측면 영상 한 편을 분석한 사례.** 한 번의 실행으로 원판·관절 오버레이 영상, 프레임별 직접 검출·시간 연결·미탐 CSV, 구간 수치 JSON을 만든다. 이 시도에서는 116프레임 모두 원판을 직접 검출했다. 수동으로 표시한 이륙 11번과 무릎 통과 27번을 영상에서 짚으면, 같은 두 프레임의 모델 박스 중심이 **160.51 px 상승**한 기록을 확인할 수 있다. [FastAPI·CLI 실행 방법](../README.md#docker-없이-실행하기)

| 면접에서 설명할 선택 | 보여줄 근거 |
| --- | --- |
| **어떤 모델을 남겼나** | 200에폭 상한 모델은 검증 사진 39장의 mAP50–95가 0.9256에서 0.9484로 올랐다. 하지만 같은 신뢰도 0.10에서 동작 중 원본 270프레임의 직접 미탐은 16장에서 32장으로 늘었다. a03 40번의 후보는 IoU가 0.963이었어도 신뢰도 0.0166으로 제외됐다. 원판 궤적이 덜 끊기는 100에폭 베이스라인을 채택했다. |

**도메인 해석의 범위.** 이륙·무릎 통과·바 접촉을 모두 수동 대조한 4명에서 수동 허브와 모델 모두 두 번째 당기기 구간의 평균 수직 속도가 더 컸다. 비교 단위는 한 사람의 한 시도다. 카메라 배율과 부하가 다른 선수 간 절대 속도나 숙련도 판정은 검증 과제로 둔다. 자세는 카메라에 가까운 쪽을 중심으로 보고, 옷에 가린 골반 소켓·원판에 가린 견봉은 추정 여부를 표시한다. 발의 방향과 가림 때문에 측면 영상만으로 발목 가동성을 판정하기 어렵다.

**다음 배포 이정표.** 현재 시연 범위는 Mac의 PyTorch 분석이다. 이후 같은 입력에서 PyTorch와 ONNX Runtime의 좌표·검출 상태·지연을 비교한 뒤, RunPod의 NVIDIA GPU에서 TensorRT를 실측한다. FastAPI·Docker 단계에서는 동일한 영상으로 API 출력까지 재현하는 것을 목표로 한다.

## 어떤 문헌을 어떤 판단에 사용했나

- Giner Godoy & Bazuelo Ruiz(2022)의 스내치 체계적 리뷰를 근거로 당기기 국면을 나눴다. 이 프로젝트에서는 트레이너가 표시한 세 이벤트와 원본 표시 시각으로 두 구간의 **평균** 수직 속도를 구한다. 문헌이 제시한 순간 속도와 직접 비교하거나 숙련도를 판정하지 않는다. [논문](https://www.accionmotriz.com/index.php/accionmotriz/article/view/225)
- Camilleri(2025)는 파워리프팅 자세 추정에서 관절 위치 오차와 관절 각도 오차를 각각 평가했다. 이 구분을 가까운 쪽 좌표 검증과 이륙→무릎 통과의 체간 각도 비교에 적용했다. 추정한 골반·견봉을 포함한 결과에는 추정 상태를 붙인다. [몰타대 석사논문](https://www.um.edu.mt/library/oar/handle/123456789/138342)
- DeVitto(2022)는 3D 마커로 바와 신체 위치를 측정했다. 측면 영상에서는 화면상 허브–견봉의 수평·수직 차이까지만 읽는다. 부상 위험이나 양측 비대칭은 이번 측정 범위를 벗어난다. [이스트캐롤라이나대 논문 11~15쪽](https://thescholarship.ecu.edu/server/api/core/bitstreams/ce6aa2c3-88dc-43fd-99bd-c91501b40554/content)
- 스내치의 부하별 속도 연구와 성공·실패 궤적 분석은 촬영거리와 부하가 다른 사람의 절대 속도를 직접 순위화하기 어려운 이유와, 시도 안에서 바의 수평 이동을 함께 볼 이유를 설명한다. [부하별 속도 연구](https://www.mdpi.com/2075-4663/8/5/59) · [2D 바벨 궤적 연구](https://www.mdpi.com/2075-4663/7/6/151)
- CrowdHuman의 가시 영역·전신 박스 구분을 참고해 머리 위 원판에 가려진 수행자의 박스를 재판독했다. D-RISE는 배경 오탐이 반복될 때 검토할 설명 방법이다. 지금까지 수행한 것은 같은 면적·질감에서 위치를 바꾼 가림 대조 실험이다. [CrowdHuman](https://www.crowdhuman.org/download.html) · [D-RISE](https://openaccess.thecvf.com/content/CVPR2021/html/Petsiuk_Black-Box_Explanation_of_Object_Detectors_via_Saliency_Maps_CVPR_2021_paper.html)

## 원판 학습 일정과 검출 신뢰도

같은 사전학습 모델과 사람별 분할로 Mac에서 두 일정을 비교했다. 입력 640, 배치 16, 시드 0을 유지했다. 200에폭 상한 실행은 96에폭에서 검증 mAP50–95가 가장 높았고 146에폭에 조기 종료했다.

| 같은 입력에서 두 best.pt 재검증 | 기존 100에폭 · patience 100 | 최대 200에폭 · patience 50 |
| --- | ---: | ---: |
| 검증 6명의 JPEG 39장 mAP50–95 | 0.9256 | 0.9484 |
| 같은 39장 TP / FP / FN (신뢰도 0.10, IoU 0.50) | 38 / 0 / 1 | 34 / 0 / 5 |
| 동작 중 수동 박스가 있는 원본 270프레임 정탐 | 254 | 238 |
| 같은 원본 프레임에서 시간 연결 포함 정탐 | 257 | 248 |

a03 40번에서 기존 박스는 신뢰도 0.317, IoU 0.956으로 정탐이었다. 새 후보는 IoU가 0.963이었지만 신뢰도는 0.0166이었다. 진단용 하한을 0.001로 낮추면 이 후보가 보인다. 같은 방식으로 새로 놓친 a03 32·40번과 b02 33·36번 네 장 모두에서 정답과 겹치는 저신뢰 후보를 확인했다.

시간 연결 후 새로 복구된 장면은 0장이고 기존에 잡았던 9장을 잃었다. 동작 중 원판 궤적에는 100에폭 가중치를 유지한다. 검증 사진 39장에는 모두 원판이 있다. 이후 [테스트 선수 3명](plate_holdout.md)의 원판을 평가했다. 원판 없는 독립 영상의 오탐률은 미측정이다.

## 65·95에폭에서 원판 궤적이 어떻게 달라졌나

같은 100에폭 설정을 다시 실행했을 때 기존 최고 가중치와 새 95에폭의 모델 상태 텐서 708개가 모두 같았다. 학습 로그에서 검증 사진 39장의 mAP50–95는 65에폭 0.92470, 95에폭 0.92547이었다.

| 동작 중 검증 6명 | 65에폭 | 95에폭 |
| --- | ---: | ---: |
| 직접 검출 미탐 / 수동 박스 270장 | 25 | 16 |
| 시간 연결 적용 후 미탐 / 같은 270장 | 19 | 13 |
| 직접 검출 공통 정탐 178장의 허브 세로 평균 절대 오차 | 1.87 px | 2.04 px |
| 시간 연결 공통 정탐 185장의 허브 세로 평균 절대 오차 | 2.13 px | 2.28 px |

95에폭에서 시간 연결까지 적용하면 a03의 26~28번과 38~40번이 복구됐다. 이전에 맞혔다가 놓친 프레임은 없었다. b02 35번에서는 시간 연결로 박스를 찾았지만 중심은 수동 허브보다 50.94 px 아래였다. 궤적 공백이 적은 기존 95에폭 best.pt를 유지하고, 허브 좌표의 오차는 별도로 평가한다. [42번 비교 노트북](../notebooks/experiments/42_plate_epoch65_95.ipynb)

## 원판 중심으로 계산한 프레임 간 상승량 오차 · 2026-11-25

운영 베이스라인 `best.pt`(입력 640, 직접 검출 기준 0.10, 기존 시간 연결)를 고정했다. 기존 검증 6명의 동작 구간에서 수동 허브가 두 장 연속 보이는 182쌍 중 양 끝의 모델 박스가 모두 정탐(IoU ≥ 0.50)인 181쌍을 채점했다. 정탐인 수동점이 있어야 계산할 수 있는 조건부 오차다. 프레임 사이에는 같은 선수의 동작이 이어져 있으므로 181쌍은 독립된 181개 시도가 아니다.

위쪽을 양수로 두고 두 프레임의 수동 허브 y좌표 차이와 예측 박스 중심 y좌표 차이를 비교했다. 각 영상의 실제 프레임 표시 시각 차이로 두 상승량을 나누면 화면상 구간 속도(px/s)가 된다. 수동점을 찍을 때 생긴 오차도 이 비교에 포함된다.

| 절대 오차 · 181쌍 | 중앙값 | 95백분위 | 최대 |
| --- | ---: | ---: | ---: |
| 한 프레임 간격의 수직 상승량 | 0.92 px | 3.20 px | 21.10 px |
| 같은 간격의 평균 수직 속도 | 24.22 px/s | 82.90 px/s | 506.45 px/s |

b02의 34→35번은 수동 58.00 px, 모델 36.90 px였다. 바로 다음 35→36번은 수동 91.00 px, 모델 109.05 px였다. 두 간격의 오차 부호가 달라 34→36번에서 합친 상승량 오차는 −3.05 px로 줄었다. 앞서 수동 이륙·무릎 통과·접촉을 모두 판독한 4명에서는 수동점과 모델 모두 뒤 구간의 평균 수직 속도가 더 컸다. 따라서 영상 안의 수직 궤적과 구간 평균은 판독 범위를 표시해 제시하고, 한 프레임 속도나 최고 속도는 별도 검증 대상으로 둔다.

**분할 점검.** 원판 학습의 실제 45장(8명)과 고정 검증 39장(6명) 및 각 내부 fold의 학습·검증 사이에 선수 ID, 영상 ID, 원본 영상 파일 해시, 프레임 키, 디코딩한 이미지 픽셀 중복은 0건이었다. 내부 검증 선수는 한 회차에만 배정됐고, 기존 검증 6명은 세 회차의 학습 및 내부 검증에 들어가지 않았다. 이 점검은 기록된 ID와 정확히 같은 파일·이미지를 기준으로 했다. 고정 검증 6명은 모델과 규칙 선택에 반복 사용했다. 배포 규칙을 고정한 뒤 [별도 선수 3명의 결과](plate_holdout.md)를 집계했다.
