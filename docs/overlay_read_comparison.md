# MPS 오버레이에서 원본을 한 번 읽는 효과

c04 한 편에서 원본을 한 번 읽고 모델별로 전처리하면 명령 전체 시간의 중앙값이 **11.30초에서 8.96초로 2.34초(20.7%) 줄었다.** 세 블록 모두 이 경로가 기존 두 번 읽기보다 빨랐다. 검증한 영상에 권하는 실행 옵션은 `--read-mode single-pass`다.

| 원본 읽기와 전처리 | 블록 1 (초) | 블록 2 (초) | 블록 3 (초) | 명령 중앙값 (초) | 분석 함수 중앙값 (초) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 두 번 읽기 · 모델별 전처리 | 10.81 | 11.62 | 11.30 | 11.30 | 9.27 |
| 한 번 읽기 · 모델별 전처리 | 9.73 | 8.96 | 8.85 | 8.96 | 6.98 |
| 한 번 읽기 · 전처리 텐서 공유 | 9.66 | 9.75 | 8.79 | 9.66 | 7.11 |

텐서 공유는 모델별 전처리보다 블록 1·3에서 약 0.06초 빨랐고 블록 2에서 0.79초 느렸다. 이 표본에서 전처리 공유의 추가 이득은 일관되지 않았다. 가장 빠른 중앙값 기준 처리량은 12.94 fps이고 완성 파일의 재생 속도는 30 fps다.

## 비교 조건과 검수

검증 선수 c04의 같은 116장을 Apple M2에서 사용했다. 원판 베이스라인과 원본 YOLO26n-pose, MPS FP32, 긴 변 640, 배치 1, 원판 연결 반경, 1080×1920 H.264 출력이 동일하다. 블록마다 세 조건의 순서를 바꿔 각 방식이 첫째·둘째·셋째 위치에서 한 번씩 실행되게 했다. 아홉 번 모두 별도 예열 없이 새 프로세스에서 실행했다. 기존 50번의 단발 기록 12.70초는 이번 대조군 집계에 포함하지 않았다.

- 기존 경로는 원판 후보를 영상 전체에서 모아 연결한 뒤 영상을 다시 읽으며 자세와 궤적을 그린다. 한 번 읽기는 현재 프레임에서 두 모델을 호출하고 같은 연결 규칙을 프레임마다 적용해 즉시 인코딩한다. 모델별 전처리 조건에서도 디코딩한 프레임을 공유한다. 텐서 공유 조건은 리사이즈·정규화·GPU 입력 이동까지 한 번 수행한다.
- 시간은 명령 시작부터 종료까지 측정했다. 측정 후 9편을 다시 디코딩해 첫 대조군과 매 프레임의 복원 픽셀을 비교했다. 모든 파일이 H.264, 1080×1920, 30 fps, 116장이었다. **복원 픽셀이 달라진 장수, 판정·결측 상태 불일치 장수, 저장한 좌표·점수·각도의 최대 차이가 모두 0**이었다. 이륙 11번부터 무릎 통과 27번까지 원판 중심은 **+160.51 px**, 체간 각도는 **−10.66°** 변했다.
- c04는 원판이 116장 모두 직접 검출된 영상이다. 별도로 기존 b02·c07 원판 후보 417프레임에서 궤적 코드 분리 전후를 대조했다. 기본 연결 규칙에서 직접 409장·연결 3장·미탐 5장이었고 선택 좌표와 연결 진단 기록이 일치했다. 다른 영상의 전체 처리 시간은 이번에 측정하지 않았다.
- 예비 측정 도중 전처리 공유 경로가 자세 추론 객체를 매번 다시 준비하는 문제를 발견했다. 영상 내에서 같은 객체를 재사용하도록 수정하고 실제 연속 프레임으로 확인한 뒤, 세 조건을 모두 다시 측정했다. 위 표에는 수정 후 실행만 포함했다.
