# RTX 3090에서 FP16이 스내치 분석값에 미친 영향

FP16은 이번 배포 시제품에 사용할 수 있다. 같은 RTX 3090에서 정밀도를 낮춰도 검사한 사진의 동작 중 새 미탐은 0건이었고, 표시한 관절의 위치 차이는 최대 0.69 px였다. 박스 겹침을 더 엄격하게 평가하면 원판 mAP50–95는 0.245%p 떨어졌다.

## 같은 입력에서 정밀도만 바꾼 결과

사람별 분할을 유지한 기존 검증 6명에서 원판 사진 39장과 이륙·무릎 통과 자세 12장을 채점했다. 원판은 베이스라인 `best.pt`, 자세는 원본 `yolo26n-pose.pt`에서 변환한 ONNX 그래프를 썼다. TensorRT 10.13.3.9, 입력 1×3×640×384, TF32 해제, 같은 전처리·후처리와 운영 기준을 적용했다. 두 엔진의 외부 입출력은 FP32다. FP16 허용 엔진은 두 모델 모두 내부 Half 텐서를 확인했다.

| 실사 지표 | Mac PyTorch FP32 | RTX 3090 TensorRT FP32 | RTX 3090 TensorRT FP16 |
|---|---:|---:|---:|
| 원판 mAP50 | 0.9897 | 0.9897 | 0.9897 |
| 원판 mAP50–95 | 0.9254 | 0.9254 | 0.9230 |
| 동작 중 직접 TP / FP / FN | 38 / 0 / 1 | 38 / 0 / 1 | 38 / 0 / 1 |
| b02 30~36번 허브 세로 평균 절대 오차 | 27.81 px | 27.81 px | 27.64 px |
| b02 이륙 20번 → 무릎 통과 30번 상승량 | +248.193 px | +248.193 px | +248.188 px |
| 동일 수행자 대응 | 12/12 | 12/12 | 12/12 |
| 가까운 쪽 관절 표시 / 저신뢰 보류 | 39 / 9 | 39 / 9 | 39 / 9 |
| 직접 찍었고 표시된 관절과의 평균 거리 (15점) | 11.64 px | 11.64 px | 11.67 px |

- **원판**. a03 2번은 두 엔진이 공통으로 놓쳤다. 정답 박스와 IoU 0.50, 신뢰도 0.10 기준에서 새 미탐과 복구는 모두 0건이었다. AP 차이는 IoU 0.60에서만 발생했다. b02 33번 검증 사진의 최대 IoU가 0.6008 → 0.5924로 바뀌며 AP60이 0.9897 → 0.9652로 내려갔다.
- **궤적**. b02 원본 30~36번은 두 엔진 모두 7/7장이 정답 박스와 대응됐고 35번은 시간 연결로 복구했다. 35번의 박스 중심은 수동 허브보다 47.94 / 48.00 px 아래였다. 이륙→무릎 통과의 수동 상승량은 +252.00 px로, 두 엔진의 구간 상승량 차이는 약 0.0054 px였다. 두 끝점의 오차가 일부 상쇄될 수 있어 이 수치만으로 순간 속도의 정확도를 판단할 수 없다.
- **자세**. 같은 수행자의 가까운 쪽 어깨·골반·무릎·발목 48점에서 표시 상태 변화는 0건이었다. 함께 표시한 39점의 좌표 차이는 평균 0.31 px, 최대 0.69 px(b02 30번 오른쪽 무릎)였다. 12장의 모델 체간 각도 차이는 최대 0.24°였다. 수동 위치 오차에는 직접 확인한 점만 썼다.
- **배포 판단**. 앞선 실험에서 합성 116프레임 영상 한 편을 저장하는 시간은 TensorRT FP32 평균 4.06초, FP16 평균 3.79초였다(각 2회). 이번 실사 실험은 그 속도 후보의 품질을 검증했다. 실사 영상 한 편의 처리 시간, 원판 없는 독립 영상의 오탐률, 새 선수의 자세 정확도는 별도 검증 범위다. [RTX 3090 처리 시간 실험](tensorrt_3090.md)

## 재현

1. 기존 46·47번 ONNX 그래프, 수동 라벨과 원본이 있는 Mac에서 57번 노트북을 순서대로 실행한다. 첫 실행은 로컬 입력과 PyTorch·ONNX Runtime FP32 대조군을 만든다. [실사 정밀도 노트북](../notebooks/experiments/57_real_frame_precision.ipynb)
2. RTX 3090에서 CUDA 텐서 연산이 되는지 확인한다. Mac의 `outputs/real_frame_precision/57_validation_v1/gpu_input/`에 있는 모델 그래프 2개, 숫자 키 입력·작업 목록, 실행 모듈 2개만 승인된 Pod의 빈 폴더에 복사한다. 선수 ID와 정답이 든 `local_frames.csv`는 Mac에 둔다.
3. 이 실험은 Linux, PyTorch 2.8.0+cu128, 드라이버 570.211.01, TensorRT 10.13.3.9와 ONNX Runtime 1.23.2를 사용했다. 해당 폴더에서 `NVIDIA_TF32_OVERRIDE=0 python precision_gpu.py`를 실행한다. 생성된 `result/`에서 `trt-*.npz` 네 개와 `real_run.json`을 Mac 실험의 `predictions/`로 가져온 뒤 노트북을 다시 실행한다. 입력과 그래프의 체크섬, 장치 및 출력 형태를 확인한 뒤 Mac의 동일한 정답으로 채점한다.

검증 사진 39장은 모두 동작 중 원판이 있는 프레임이다. 허브용 영상 프레임 8장과 자세용 12장 중 2장이 겹친다. JPEG와 원본 영상에서 읽은 픽셀을 구분하여 총 57개 입력을 사용했다. 준비 파일, 그래프, 이미지와 예측 배열은 로컬 실험 폴더에 보관한다.
