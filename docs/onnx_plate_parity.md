# 원판 검출 PyTorch·ONNX 출력과 지연 비교

## 결과와 결정

Apple M2 CPU에서 기존 원판 베이스라인을 FP32 ONNX로 내보내고 동일한 입력을 비교했다. 검증 6명의 원본 영상 687프레임에서 두 런타임의 선택 출처가 모두 같았다. 이 체크포인트와 입력 형태에서 ONNX Runtime을 원판 배포 후보로 채택한다. 다음 비교는 원본 YOLO26n-pose의 PyTorch·ONNX 출력이다.

| 지표 | PyTorch | ONNX Runtime |
| --- | ---: | ---: |
| 프레임당 추론 중앙값 | 28.60 ms | 18.81 ms |
| 프레임당 추론 p95 | 36.98 ms | 22.91 ms |
| 직접 검출 / 시간 연결 / 출력 없음 (687장) | 662 / 5 / 20 | 662 / 5 / 20 |
| 수동 박스와 IoU 0.50 이상 (라벨 56장) | 56/56 | 56/56 |
| b02 35번 선택 점수 | 0.06019684 | 0.06019628 |
| c04 11→27번 원판 중심 상승량 | +160.51379 px | +160.51379 px |

중앙값은 34.2%, p95는 38.1% 감소했다. 한 대의 Mac에서 실행한 한 번의 비교이며 영상 디코딩, 전처리, NMS, 시간 연결, 파일 입출력은 지연 측정에서 제외했다. 20장은 두 런타임 모두에서 선택 박스가 없던 장수다. 전체 영상에 프레임별 정답이 있는 것은 아니므로 실제 미탐 수는 수동 박스로 평가한 범위에서 해석한다.

## 박스·신뢰도 일치

전체 3,220쌍의 NMS 후 후보를 프레임 안에서 좌표로 일대일 대응했다. 후보 수가 다른 프레임은 0장이었다. 후보의 원본 좌표 최대 차이는 0.001221 px, 신뢰도 최대 차이는 0.00000298이었다. 추적에서 실제 선택한 박스 좌표 최대 차이는 0.000488 px였다. 미리 정한 허용오차는 좌표 0.10 px, 신뢰도 0.0001이다. 44번 원본 56장의 선택 출처·정탐·좌표·신뢰도도 허용오차 안에서 재현했다.

b02 35번에서는 두 모델 모두 신뢰도가 직접 기준 0.10보다 낮았고 시간 연결로 복구했다. PyTorch 좌표는 (105.95177, 464.77740, 400.22644, 785.10797), ONNX 좌표는 (105.95172, 464.77731, 400.22638, 785.10791)이었다. 두 박스의 수동 원판과의 IoU는 각각 약 0.61379였다.

## 측정과 재현

- 입력 크기 설정은 기존과 같은 640이다. 세로 영상 여섯 편에서 실제 텐서는 RGB FP32 `[1, 3, 640, 384]`였다. 일괄 처리 크기 1로 내보낸 고정형 그래프이므로 다른 종횡비·입력 형태는 별도 검증 대상이다.
- 변환은 Ultralytics 8.4.202, ONNX 1.23.2, opset 17, FP32, 단순화 끔으로 진행했다. ONNX 검사기와 Netron 9.3.7의 그래프 리더로 구조를 점검했다. 입력 `images`와 출력 `output0`(`[1, 5, 5040]`)을 확인했다. NMS는 두 런타임에서 동일한 외부 코드로 적용했다. 원시 출력의 좌표 최대 차이는 입력 기준 0.006836 px, 점수 최대 차이는 0.00001001이었다.
- macOS 15.7.4, PyTorch 2.15.0, ONNX Runtime 1.32.0의 CPUExecutionProvider에서 연산 스레드를 각각 4개로 설정했다. 영상마다 런타임별 10회 예열했다. 각 프레임은 두 모델에 한 번씩 입력하고 선실행 순서를 번갈아 사용했다. ORT 유휴 스레드 스핀은 껐다.
- 후보 하한 0.001, NMS IoU 0.70, 직접 검출 기준 0.10, 시간 연결 반경은 직전 박스 너비의 0.5배다. 45번 박스 크기 보정은 적용하지 않았다.

실행 조건 참고 자료는 [Ultralytics 내보내기 안내](https://docs.ultralytics.com/modes/export/)와 [ONNX Runtime 스레드 설정](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)이다.
