# 원판 검출 모델의 학습 일정 비교

기존 RTX 3090 대조군의 최대 100에폭·patience 100을 기록상 기준으로 유지한다. 새 일정은 a03의 가림 구간과 직접 판독한 허브의 세로 오차를 개선했지만, 시간 연결 후 동작 중 미탐이 한 장 늘어 사전에 정한 채택 조건을 통과하지 못했다.

## 무엇을 고정했나

두 실행 모두 같은 원본 `yolo26n.pt`, 선수별 분할(학습 8명 45장·검증 6명 39장), 입력 640, 배치 16, 시드 0, CutMix 0을 사용했다. 실제 옵티마이저는 모두 AdamW(초기 학습률 0.002), 데이터 로더는 3개였다. 최대 에폭과 patience를 함께 바꾸면 학습률 감소 속도와 마지막 10에폭의 모자이크 종료 시점도 달라진다. 이번에는 두 학습 일정의 효과를 비교했다.

새 실행은 RunPod Community의 실제 GeForce RTX 3090 24GB에서 200에폭까지 진행했다. GPU 검증 mAP50–95 최고점은 기존 91에폭, 새 일정 179에폭이었다. 새 최고점 이후 21에폭 만에 상한에 도달해 조기 종료는 발동하지 않았다. 가중치 초기화부터 최종 검증까지 119.75초가 걸렸다. 두 실행은 PyTorch 2.8.0+cu128과 Ultralytics 8.4.202를 사용했다. 호스트 드라이버는 기존 580.95.05, 새 실행 595.91.07이었다.

## 같은 검증 영상에서 비교한 결과

Mac CPU에서 두 단독 모델의 best.pt로 검증 원본 6편 687프레임을 순서대로 처리했다. 동작 중 수동 박스가 있는 270장에서 기존 시간 연결을 적용하고 IoU 0.50 이상이면 정탐으로 셌다. 허브 세로 오차는 두 모델 모두 정탐이고 사람이 허브를 직접 확인한 같은 프레임에서 계산했다.

| 시간 연결 적용 지표 | 100 / 100 | 200 / 30 | 채택 기준 |
| --- | ---: | ---: | --- |
| 동작 중 미탐 | 17 / 270 | 18 / 270 | 17장 이하 |
| a03 최장 연속 미탐 | 13프레임 | 12프레임 | 13프레임 이하 |
| 수동 허브 세로 평균 절대오차 · 공통 185장 | 2.142px | 1.827px | 증가 1px 이하 |
| 고정 검증 사진 39장 mAP50–95 | 0.88604 | 0.88416 | 참고 지표 |

시간 연결을 끈 프레임별 YOLO의 미탐은 20장에서 18장으로 줄었다. 연결을 켰을 때 기존 일정은 3장을 더 복구했고, 새 일정은 미탐 장수가 같았다. 배포 시제품에서는 Mac 베이스라인과 선택형 CutMix 보조 조합을 사용한다. 이번 비교 대상은 3090 단독 모델이다.

## 미탐 한 장 차이의 내용

- **a03**에서 14·25·26·27번을 새로 찾았다. 2–14번이 연속 미탐이던 구간에서 14번을 복구해 최장 길이가 12프레임이 됐다.
- **b02**에서 31·33·34·35·36번을 새로 놓쳤고, 기존에도 놓쳤던 32번과 이어져 31–36번이 6프레임 연속 미탐이었다. 새로 놓친 다섯 장에서 모두 직접 검출 박스가 있었다. 새 박스 면적은 수동 박스의 약 36–44%였고, 다섯 장 모두 IoU 0.50 미만이었다.
- **b02 35번**에서 신뢰도는 0.295에서 0.916으로 올랐지만 IoU는 0.516에서 0.368로 내려갔다. 한편 박스 중심과 수동 허브의 세로 차이는 절댓값 13.96px에서 0.94px로 줄었다. 이 프레임에서 원판 바깥 경계를 맞히는 성능과 허브에 가까운 중심을 내는 성능은 서로 다른 방향으로 변했다. 두 모델 공통 정탐 185장에는 이 프레임을 포함하지 않았다.
- 나머지 검증 4명(a05·b03·c04·c08)은 두 일정 모두 동작 중 미탐 0장이었다.

허브 오차는 평균 0.316px 개선됐지만 두 미탐 지표가 모두 유지되어야 한다는 조건이 있었다. 단일 시드, 검증 선수 6명의 관찰이며, 이 결과만으로 patience 100이 최적이라고 판단할 수는 없다.

로컬 검산과 대표 프레임은 [70번 비교 노트북](../notebooks/experiments/70_plate_3090_schedule.ipynb)에서 확인한다. 프로젝트 루트에서 아래 명령으로 두 모델을 다시 채점할 수 있다.

```bash
uv run --frozen --env-file .env python -m wlcv.evaluation.schedule_3090_review \
  outputs/plate_3090_schedule/20261126/runs/schedule200 \
  outputs/plate_3090_schedule/20261126/paired_review
```
