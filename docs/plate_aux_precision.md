# 원판 추적·상승량 보조 모델의 ONNX와 TensorRT FP16 검증

## 검증 목적

FastAPI 연결 전에 원판 베이스라인과 CutMix의 빈 프레임 복구, 두 수동 시점의 코사인 상승량을 같은 입력으로 검증했다. 배포 추적기와 같은 PyTorch 판정이 기준이다. 0.0005 코사인과 CutMix는 각각 별도 ONNX와 별도 TensorRT 엔진으로 만들었다.

## 실제로 처리한 입력

기존 검증 선수 6명의 원본을 각 영상 0번부터 마지막 확인 동작까지 읽었다. 준비 전 55장으로 시간 연결 이력을 초기화하고 동작 478장을 포함해 총 533장이다. b02는 접촉까지, 나머지 다섯 편은 피니시까지 포함했다. 검증 6편 전체 687장 중 동작 이후 154장은 이번 추론 범위 밖이다. 수동 정답 박스가 있는 동작 중 270장에서 IoU 0.50으로 정탐·미탐·오탐을 셌다.

이미지를 한 번 전처리해 배치 1, RGB 640×384, CHW 순서의 입력을 만들었다. Mac과 GPU는 같은 번호의 8비트 배열을 255로 나눈 FP32 입력을 사용했다. 추론 사진과 함께 선수 ID를 복원하는 번호표, 수동 박스와 허브는 Mac에 보관했다. RunPod에는 번호만 붙인 입력, 그래프와 실행 파일을 SSH로 전송했다.

베이스라인과 CutMix는 각각 533장에서 독립적으로 궤적을 갱신했고, 베이스라인이 비었을 때만 CutMix 출력을 골랐다. 코사인은 무릎 통과·접촉 12장에서만 추론했다. 두 시점 모두 직접 검출과 추적 박스 간 IoU가 0.50 이상이면 코사인, 한쪽이라도 보류되면 기존 추적 좌표 두 점으로 상승량을 계산했다. 모든 런타임의 원시 출력에 같은 NMS·좌표 복원·추적·채점 코드를 Mac에서 적용했다.

## 배포 판단

원판 세 모델 전체를 FP16으로 실행해도 수동 박스 270장에서 265장 정탐·5장 미탐·0장 오탐이었다. 미탐은 모두 a03의 2·3·7·8·9번으로 같은 프레임에서 발생했고, 좌표가 연속으로 비는 최장 길이도 3프레임이었다. a03에서 CutMix가 복구한 4·5·6·10·11·12·13·14번 8장은 그대로 정탐이었다.

수동 허브 상승량 평균 절대오차는 PyTorch 2.23144px, ONNX 2.23144px, 전체 FP16 2.34967px였다. FP16의 증가는 0.11823px다. CutMix만 FP16일 때는 기준과 같았고, 코사인만 FP16이면 2.29396px, 여기에 주 모델까지 FP16으로 바꾸면 2.34967px였다. a03 접촉 25번의 코사인 최고 신뢰도는 PyTorch 0.09713, FP16 0.09637로 모두 직접 검출 기준 0.10보다 낮았다. 기존 추적으로 계산한 a03의 상승량이 70.334px에서 70.000px로 변해 여섯 선수 중 엔진 간 차이가 가장 컸다.

검출·시간 연결 용도로 RTX 3090 FP16을 시제품에 쓸 근거를 얻었다. 상승량을 보고할 때는 해당 엔진의 실측치 2.35px를 표기한다. 2.23px를 그대로 요구하면 Mac FP32 결과를 기준으로 한다. 이 수치는 6명에게서 무릎 통과→접촉 구간을 한 번씩 잰 결과다. 프레임별 순간 속도의 정확도, 신규 선수 성능, 서비스 전체 지연시간은 별도 측정이 필요하다.

## 실행 환경

Mac FP32 대조군은 Ultralytics 8.4.202, PyTorch 2.15.0, ONNX 1.23.2, ONNX Runtime 1.32.0 CPU를 사용했다. ONNX는 opset 17, 정적 입력, 외부 NMS다. GPU는 Secure Cloud RTX 3090, PyTorch 2.8.0+cu128, TensorRT 10.13.3.9, 드라이버 595.112.07에서 TF32를 껐다. 엔진의 외부 입출력은 FP32이고, 내부 출력에 Half를 사용한 레이어를 모델별로 확인했다. baseline 234개, cutmix 220개, cosine 210개.

## 재현 방법

1. Mac 프로젝트 루트에서 아래 순서로 입력 묶음과 로컬 대조군을 만든다. 이 예시는 새 실행 폴더를 사용한다.

```sh
review=outputs/plate_aux_trt/replay
python -m wlcv.evaluation.plate_aux_precision "$review" prepare
python -m wlcv.evaluation.plate_aux_precision "$review" controls
python -m wlcv.evaluation.plate_aux_precision "$review" pytorch
python -m wlcv.evaluation.plate_aux_precision "$review" onnx
```

2. RTX 3090의 빈 실행 폴더에 `gpu_input/`의 내용과 `wlcv/evaluation/plate_aux_gpu.py`, `wlcv/evaluation/tensorrt_3090.py`를 복사한다. 이 입력에는 복원 가능한 선수 영상 프레임이 있어 실사 처리를 허용한 호스트를 사용한다. TensorRT 10.13.3.9, PyTorch 2.8.0+cu128 및 ONNX Runtime이 있는 환경에서 `NVIDIA_TF32_OVERRIDE=0 python plate_aux_gpu.py`를 실행한다.
3. 생성된 `result/`를 Mac의 `$review/gpu_result/`로 회수하고 체크섬을 대조한다. 엔진 파일과 원시 출력을 보존한 뒤 아래 명령으로 채점한다.

```sh
for runtime in cutmix-fp16 cosine-fp16 aux-fp16 trt compare; do
    python -m wlcv.evaluation.plate_aux_precision "$review" "$runtime"
done
```

[77번 노트북](../notebooks/experiments/77_plate_aux_precision.ipynb)에서 `folder`를 해당 실행 폴더로 정하고 전체 셀을 실행하면 비교표·선수별 오차 그래프·a03과 b02의 실제 박스를 다시 확인할 수 있다. ONNX와 엔진은 이 검증의 정적 입력 크기를 사용한다.
