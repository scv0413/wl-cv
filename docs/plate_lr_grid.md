# 72. 원판 검출의 초기 학습률과 선형·코사인 감소 비교

원판 검출을 더 검증할 후보로는 **lr0=0.0005, cos_lr=True**가 가장 균형이 좋았다. 기존 200/30과 비교해 동작 중 미탐은 18장→15장, 채점한 동작 중 오탐은 6장→0장이었다. 다만 좌표가 비는 프레임은 12장→15장으로 늘었다. 기존에 좌표가 있었던 a03 27·28번과 b02 35번에서 끊겼다. 최장 누락은 둘 다 12프레임이었다. 무릎 통과→접촉의 수동 허브 상승량 오차는 기존 1.58px, 새 후보 2.47px였다. 선수별 궤적을 제공하는 배포 시제품은 현 구성을 유지하고, 새 단일 모델은 검출 후보로 보관한다.

학습률 0.0005에서 선형과 코사인은 미탐이 15장으로 같았다. 코사인을 쓰면 좌표 누락이 38장→15장으로 줄었고 상승량 오차는 1.99px→2.47px로 커졌다. mAP가 가장 높은 0.0005 선형의 좌표 누락 38장은 모두 a03에서 발생했다. 학습률 0.001에서는 코사인이 선형보다 박스 미탐을 3장 줄였지만 전체 좌표 누락은 15장→28장으로 늘었다. 코사인의 효과는 초기 학습률에 따라 달랐다.

b02 36번에서 기존 200/30의 IoU는 0.412, 0.0005 코사인은 0.965였다. b02의 접촉 직전부터 기존 모델이 놓친 31·32·33·34·36번을 새 후보가 복구했다. 같은 선수의 수동 상승량은 326px이고 기존 모델은 325.36px, 새 후보는 324.29px로 측정했다. 36번 박스를 더 잘 맞힌 효과와 두 시점의 중심으로 계산한 상승량 개선은 이 사례에서도 일치하지 않았다.

## 학습 조건

RunPod Community의 GeForce RTX 3090 24GB 한 대에서 네 조건을 순차 학습했다. 네 조건의 NVIDIA 드라이버는 580.65.06, 기존 200/30 대조군의 드라이버는 595.91.07이었다. 선수별 분할(학습 8명 45장, 검증 6명 39장), 원본 yolo26n.pt, 최대 200에폭, patience 30, 입력 640, 배치 16, 시드 0, lrf 0.01과 증강을 고정했다. 네 실행은 각각 같은 원본 가중치에서 시작했다. 실제 종료 에폭의 차이도 같은 조기 종료 규칙을 적용한 결과에 포함했다. PyTorch 2.8.0+cu128, Ultralytics 8.4.202, 장치 및 드라이버는 NVIDIA GeForce RTX 3090, 580.65.06, 24576 MiB이었다. 네 학습 및 최종 검증의 실측 시간 합은 378.69초다.

optimizer=auto는 지정한 lr0를 무시하므로 기존 실행에서 실제로 선택된 AdamW를 명시했다. β1=0.9, β2=0.999, 워밍업 바이어스 시작 학습률 0을 고정하고 런타임의 파라미터 그룹을 확인했다. cos_lr가 꺼진 경우 선형 감소, 켜진 경우 코사인 감소를 사용한다. 기존 200/30은 실제 lr0=0.002의 선형 스케줄이며 별도 실행의 참고치다.

## 같은 검증셋의 결과

Mac CPU에서 각 모델로 검증 영상 6편 687프레임을 처음부터 처리했다. 동작 구간은 ready부터 마지막 수동 시점까지이며, finish가 없는 하프 동작은 마지막으로 표시한 시점에서 끝난다. 시간 연결 후 동작 중 수동 박스 270장의 미탐(IoU 0.50 기준), 전체 동작 478프레임에서 좌표가 비는 길이, 무릎 통과→접촉 시점의 수동 허브 상승량 오차를 비교했다. mAP는 고정 검증 39장에서 별도로 측정했다. 원판이 있는 프레임에서 선택된 박스가 IoU 0.50에 못 미치면 오탐과 미탐에 각각 한 건씩 센다. 출력 박스가 없는 경우에는 미탐만 센다. 준비 전·종료 후 채점 가능 수와 오탐은 노트북에 따로 실었다. 상승량 평균 절대오차는 다섯 모델에서 모두 측정된 선수 6명의 평균이다.
