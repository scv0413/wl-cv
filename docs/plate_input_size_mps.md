# 원판 입력 640과 512에서 MPS 오버레이 시간과 궤적 비교

원판 입력 기본값 640을 유지한다. 입력 512는 c04에서 네 번 모두 조금 빨랐고, b02에서는 네 번 중 세 번 느렸다. 수동 판독으로 평가한 동작 중 미탐 수는 같았다. b02의 허브 위치 오차와 두 시점 사이의 상승량 오차는 서로 다른 결과를 보였다.

## 영상 한 편을 저장하는 시간

두 영상 모두 원본이 116장이다. 시간은 명령 시작부터 오버레이 MP4 인코더 마감, CSV·JSON 저장 및 프로세스 종료까지의 초 단위 실측값이다. 네 번의 중앙값을 비교했다.

| 영상 | 원판 입력 | 1회 | 2회 | 3회 | 4회 | 명령 전체 중앙값 | 분석 함수 중앙값 |
|---|---:|---:|---:|---:|---:|---:|---:|
| c04 | 640 | 10.42 | 8.58 | 8.78 | 8.70 | 8.74 | 6.85 |
| c04 | 512 | 9.00 | 8.50 | 8.44 | 8.67 | 8.58 | 6.71 |
| b02 | 640 | 8.07 | 7.92 | 7.88 | 7.73 | 7.90 | 6.00 |
| b02 | 512 | 7.78 | 7.99 | 8.07 | 7.99 | 7.99 | 6.07 |

Mac M2 · MPS · FP32 · 배치 1 · 원판 베이스라인 `best.pt` · 원본 YOLO26n-pose 640. 매 실행에서 새 프로세스로 원본을 한 번 읽고 두 모델이 따로 전처리했다. 직접 검출 기준 0.10, 시간 연결 반경 0.5배, 인코더와 원본 크기를 고정했다. 네 블록에서 영상별로 각 입력이 두 번씩 먼저 실행되도록 순서를 바꿨다. 결과 검수는 시간 측정 후 수행했다. 완성된 16개 영상을 끝까지 디코딩했고, 모든 파일이 원본과 같은 크기·장수였다. 같은 조건의 네 프레임 표가 일치했고, 두 입력 사이에서 자세 출력과 원본 시각도 일치했다.

## 동작 중 미탐

| 영상과 동작 구간 (양 끝 포함) | 동작 장수 | 직접 / 시간 연결 / 출력 없음 (두 입력 동일) | 정답 박스 대조 | IoU 0.50 기준 미탐 (640 / 512) |
|---|---:|---:|---:|---:|
| c04 · ready 11 → finish 107 | 97 | 97 / 0 / 0 | 69장 | 0 / 0 |
| b02 · ready 20 → 접촉 36 | 17 | 16 / 1 / 0 | 17장 | 0 / 0 |

c04 79~106번 28장은 기존 고정 검수표에서 수동 박스가 비어 있어 IoU 집계에서 제외했다. b02는 하프 동작 영상으로 접촉이 마지막 수동 이벤트다. 두 설정에서 직접 검출을 놓친 35번은 시간 연결 후 모두 정답 박스와 매칭됐다. IoU는 640에서 0.614, 512에서 0.708이었다. 동작 중 수동 박스가 있는 86장에서 새로 얻거나 잃은 정탐은 0장이었다.

## b02의 허브 높이와 상승량

최초 연속 판독 30~36번에 대해 같은 프레임에서 선택한 모델 박스 중심 y와 수동 허브 y를 비교했다. 양수는 모델 중심이 화면 아래에 있다는 뜻이다. 모든 행에서 두 입력 모두 정답 원판과 매칭됐다.

| b02 프레임 | 640 세로 오차 (px) | 512 세로 오차 (px) |
|---:|---:|---:|
| 30 | +9.70 | +13.20 |
| 31 | +9.99 | +24.44 |
| 32 | +19.98 | +33.95 |
| 33 | +41.34 | +8.87 |
| 34 | +35.84 | +37.78 |
| 35 | +47.94 | +38.09 |
| 36 | +29.89 | +16.70 |

7장 세로 절대오차 중앙값은 29.89 → 24.44 px, 평균은 27.81 → 24.72 px였다. 512에서 33·35·36번은 허브에 가까워졌고 30·31·32·34번은 멀어졌다. 33번의 큰 개선 하나를 다른 선수나 전체 궤적에 일반화하기는 어렵다.

| b02 이륙 20 → 무릎 통과 30 | 20번 y (px) | 30번 y (px) | 상승량 (px, 위쪽 +) | 수동 상승량과 차이 |
|---|---:|---:|---:|---:|
| 수동 허브 | 1064.00 | 812.00 | +252.00 | — |
| 원판 640 | 1069.89 | 821.70 | +248.19 | −3.81 |
| 원판 512 | 1067.13 | 825.20 | +241.93 | −10.07 |

이륙에서 512의 중심은 수동 허브에서 3.13 px 아래, 무릎 통과에서는 13.20 px 아래였다. 끝점에서 오차가 더 커져 상승량을 10.07 px 작게 잡았다. 640의 두 오차는 5.89와 9.70 px였다. 512의 상승량은 640보다 6.26 px 작았다. 두 시점의 수동 허브는 한 판독자의 화면상 추정이며, 이 비교는 실제 거리나 속도를 검증하지 않는다.
