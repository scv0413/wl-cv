# 원판 보조 모델의 복구 효과와 오버레이 영상 완료 시간

Mac에서 단일 원판 모델을 쓰는 비용과 Mac 베이스라인에 3090 CutMix 가중치를 보조로 추가하는 비용을 비교했다. 실행 장치는 두 조건 모두 같은 Mac MPS다. 재학습은 없었다. 두 조건에 66번의 궤적 경계 예외를 적용했다. 보조 모델은 독립적인 과거 이력을 유지하도록 모든 프레임을 추론하며, 주 모델의 선택이 비었을 때만 결과에 사용한다.

## 측정 범위

같은 원본을 한 번 디코딩하고 원판·원본 YOLO26n-pose를 입력 640, 배치 1로 추론했다. 같은 그리기 코드로 원판과 가까운 관절을 표시하고 원본 해상도·프레임 속도로 H.264 영상을 저장했다. 영상별·조건별로 새 프로세스에서 4회씩 실행해 총 16편을 완성했다. 단일 먼저와 보조 먼저를 각각 2회 배치했다. 별도 예열은 없었다.

아래 시간은 **영상 열기 직전부터 인코더 종료가 반환될 때까지** 실측한 4회의 중앙값이다. 가중치 파일 로딩과 Python 시작은 이 열에서 제외했고, 첫 추론 호출의 초기화는 포함했다. 추가 시간과 비율은 두 조건의 중앙값 차이로 계산했다.

| 영상 | 단일 중앙값 (최소–최대) | 보조 포함 중앙값 (최소–최대) | 추가 시간 | 동작 중 수동 정탐 단일 → 보조 |
|---|---:|---:|---:|---:|
| a03 · 122프레임 | 6.23초 (6.04–7.33) | 8.48초 (8.38–8.55) | +2.25초 (+36.1%) | 27/40 → 35/40 |
| c04 · 116프레임 | 7.08초 (7.01–7.20) | 9.28초 (8.95–9.44) | +2.21초 (+31.2%) | 69/69 → 69/69 |

프로세스 시작, 모델 준비, CSV·타이밍 저장과 종료까지 포함한 명령 전체 중앙값은 a03에서 8.33초 → 10.53초, c04에서 9.14초 → 11.41초였다. 속도는 기기와 이 실행 경로에서 측정한 값이다.

## 원본 프레임에서의 차이

각 반복에서 a03 4·5·6·10·11·12·13·14번의 수동 원판 박스를 보조 모델로 복구했다. 같은 8장이 네 차례 반복된 결과다. 동작 중 새로 잃은 정탐은 0장이었다. 전체 122장에서 원판 출력이 비어 있는 장수는 15장에서 7장으로 줄었다. c04 116장에는 보조 모델의 결과가 선택된 프레임이 없었다. 두 조건 모두 수동 박스가 있는 동작 중 69장을 맞혔다.

16개 MP4 모두 재디코딩해 장수·해상도·프레임 속도·코덱을 확인했다. 67번 노트북에서 저장 영상의 a03 14번과 c04 27번을 직접 비교할 수 있다. 개별 소요 시간, 복구·손실 프레임, 선택 모델, MP4는 로컬에 보존한다.

## 배포 판단

기본 시연에는 단일 모델을 유지한다. 실제 가림이 있는 영상에서 궤적을 더 오래 확보할 필요가 있을 때는 두 모델을 사용하는 정밀 분석 옵션이 타당하다. 같은 검증 영상을 반복 측정했으므로 영상 종류별 평균 효과나 새 선수에서의 재현성은 앞으로 검증할 부분이다. 이 비교에서 배포 기본 설정을 바꾸지는 않았다.
