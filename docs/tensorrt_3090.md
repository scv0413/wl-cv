# RTX 3090에서 원판·자세 오버레이 한 편을 저장하는 데 걸린 시간

## 영상 한 편의 실제 완료 시간

Community RTX 3090 한 대에서 같은 합성 H.264 영상(1080×1920, 30 fps, 116프레임)을 처리했다. 각 실행은 새 Python 프로세스에서 시작했다. 모델 두 개를 불러오고, 영상을 한 번 디코딩해 원판·수행자 후보를 추론하고, NMS·좌표 복원·박스 표시를 거쳐 H.264와 CSV를 저장한 뒤 프로세스가 종료될 때까지 벽시계로 쟀다. 시작 순서는 표 순서와 그 역순이었다. 매 실행 후 타이머 밖에서 완성 영상 116장과 CSV 116행을 확인했다.

| 실행 방식 | 1회 (초) | 2회 (초) | 평균 (초) | 완성 영상 fps |
| --- | --- | --- | --- | --- |
| PyTorch CUDA FP32 | 5.30 | 4.86 | 5.08 | 22.84 |
| ONNX Runtime CUDA FP32 | 4.91 | 6.13 | 5.52 | 21.02 |
| TensorRT FP32 | 3.72 | 4.40 | 4.06 | 28.57 |
| TensorRT FP16 허용 | 3.89 | 3.69 | 3.79 | 30.62 |

TensorRT FP16의 평균은 PyTorch에서 25.4%, TensorRT FP32에서 6.7%(0.27초) 단축됐다. 첫 번째 반복에서는 FP32가 0.17초 빨랐고 두 번째에는 FP16이 0.71초 빨랐다. 이 호스트·합성 영상에서 두 번씩 얻은 결과다. ORT CUDA는 두 모델 호출이 PyTorch보다 짧아도 전체 명령 평균은 0.44초 길었다.

## 어느 단계에 시간이 들었나

| 실행 방식 | 모델 로딩 (초) | 영상 열기~저장 (초) | 두 모델 호출 (초) | 인코더 쓰기·종료 (초) | 전체 중 두 모델 (%) |
| --- | --- | --- | --- | --- | --- |
| PyTorch CUDA FP32 | 0.31 | 3.57 | 1.29 | 0.90 | 25.39 |
| ONNX Runtime CUDA FP32 | 0.34 | 3.53 | 1.03 | 1.17 | 18.68 |
| TensorRT FP32 | 0.33 | 2.55 | 0.38 | 0.88 | 9.34 |
| TensorRT FP16 허용 | 0.31 | 2.27 | 0.28 | 0.66 | 7.40 |

‘영상 열기~저장’에는 오른쪽 두 단계가 포함된다. 인코더 시간은 FFmpeg 파이프에 쓰면서 기다린 시간과 종료 대기의 합이다. 인코더는 추론과 동시에 동작한다. 전체 시간에는 공통 Python 라이브러리 시작·종료 비용도 들어간다. GPU 엔진 빌드와 합성 원본 생성은 별도로 진행했다. 시간 연결, 수행자 선택, 관절·코칭 지표는 이 합성 오버레이의 범위 밖이다.

## 모델 추론과 출력 좌표

| 실행 방식 | 원판 p50 / p95 (ms) | 자세 p50 / p95 (ms) | 원판 / 자세 fps |
| --- | --- | --- | --- |
| PyTorch CUDA FP32 | 17.90 / 20.72 | 4.52 / 4.63 | 54.59 / 220.49 |
| ONNX Runtime CUDA FP32 | 5.81 / 7.43 | 3.06 / 3.09 | 165.45 / 327.74 |
| TensorRT FP32 | 2.81 / 3.12 | 1.45 / 1.46 | 347.15 / 690.76 |
| TensorRT FP16 허용 | 2.28 / 2.43 | 0.94 / 0.96 | 430.98 / 1057.48 |

실제 모델 입력은 배치 1, RGB 640×384(긴 변 640)였다. GPU에 올려 둔 고정 난수 텐서 12개를 네 방식에서 공유했다. 모델마다 24회 예열 후 60회씩 네 블록을 돌면서 순서를 바꿨다. 240번의 동기화된 호출로 중앙값·p95를 구했고 fps는 전체 호출 수를 합산 시간으로 나눴다. 엔진 빌드 시간은 원판 FP32 119.1초 / FP16 허용 355.2초 · 자세 FP32 118.4초 / FP16 허용 417.8초였다.

## 같은 TensorRT 엔진에서 FP16 허용의 효과

| 직접 비교 항목 | 차이 p95 | 최대 차이 |
| --- | --- | --- |
| 원판 박스 (px) | 0.180909 | 3.22827 |
| 원판 점수 | 3.62992e-06 | 0.000280621 |
| 자세 관절 (px) | 0.537292 | 17.2511 |
| 자세 관절 점수 | 0.00529479 | 0.0639219 |

첫 표의 원시 출력은 PyTorch FP32를 기준으로, 두 번째 표는 TensorRT FP32를 기준으로 계산했다. 텐서마다 같은 순서의 5,040개 후보를 짝지었다. NMS 이전의 낮은 신뢰도 후보도 포함된다. 입력 기준 좌표와 점수의 일치도를 나타내며, 실제 허브·관절 위치 오차나 mAP는 실사 정답으로 따로 확인해야 한다.

난수 텐서에서는 모델당 60,480개 후보 중 원판 0.10·수행자 0.25 기준을 통과한 후보가 두 정밀도 모두 0개였다. 별도 합성 영상에서 낮은 표시 기준(원판 0.001)으로 NMS 후 그린 원판 후보는 FP32 8,981개, FP16 8,905개로 각 반복에서 같았다. 합성 무늬에 그린 박스로 실제 원판 미탐률은 구할 수 없다. 자세 점수 0.25를 넘은 수행자도 0명이어서 관절 좌표 최대 차이 17.25 px를 실제 선수의 관절 이동으로 해석할 수 없다.

## 배포 판단과 사용 비용

TensorRT FP16은 속도 후보로 남긴다. 두 모델 호출은 0.28초(전체 3.79초의 7.4%)였고 후보 후처리·그리기에 0.79초가 들었다. 이 상태에서는 4090 대여를 보류한다. 현재 입력 범위에서 FP16을 운영 기본값으로 채택하기 위한 실사 mAP·허브·관절 검증은 남아 있다.

Pod 생성부터 종료 확인까지 한국 시간 22:05:38~22:44:30, 실측 38분 52초였다. GPU 요율 $0.22/시간을 대입한 예상 비용은 $0.143이다. 환경 설치와 네 엔진 빌드를 포함하며, 청구서 기재 금액은 별도로 확인해야 한다.

## 실행 환경과 재현

RTX 3090 24GB, 드라이버 570.211.01, PyTorch 2.8.0+cu128, CUDA 12.8, ONNX Runtime GPU 1.23.2, TensorRT 10.13.3.9, Ultralytics 8.4.202. 호스트 CPU는 Intel i7-11700F, FFmpeg 6.1.1을 사용했다. OpenCV는 2스레드, CPU libx264는 veryfast·2스레드다. PyTorch와 ORT·TensorRT FP32에서 TF32를 끄고 ORT는 CUDA I/O binding, TensorRT는 네이티브 엔진을 사용했다. 엔진 검사에서 FP16 허용 시 Half와 Float 내부 텐서가 모두 보였고 외부 입출력은 FP32였다. ORT 프로파일은 원판 274개, 자세 300개 실행 노드를 모두 CUDA에 배치했다. 이 구현은 기본 CUDA 스트림을 사용했다. TensorRT가 추가 동기화 가능성을 경고했으므로 이 지연을 하드웨어의 최고 속도로 일반화할 수 없다.

1. Mac의 46·47번 참조 폴더에서 `settings.json`과 ONNX 파일을 확인한다. `wlcv.evaluation.tensorrt_bundle.prepare_bundle(새_폴더, 원판_참조_폴더, 자세_참조_폴더)`를 실행하면 체크섬과 합성 출력이 확인된 추론 전용 파일이 생긴다. 생성된 모델·코드 전용 폴더만 Pod에 올린다.

2. Linux RTX 3090 환경에서 위 PyTorch·CUDA 조합과 FFmpeg를 준비한다. `python -m pip install onnxruntime-gpu==1.23.2 tensorrt-cu12==10.13.3.9 ultralytics==8.4.202`로 라이브러리를 설치한다.

3. 모델 폴더에서 `NVIDIA_TF32_OVERRIDE=0 python benchmark.py`를 실행하고 이어서 `NVIDIA_TF32_OVERRIDE=0 python synthetic_video.py`를 실행한다. 회수한 JSON 파일을 Mac의 `outputs/tensorrt_3090/<실행 폴더>/`에 놓으면 [56번 노트북](../notebooks/experiments/56_tensorrt_3090.ipynb)에서 두 실행의 표와 그래프를 확인할 수 있다. 기존 선수 영상의 정확도는 [Mac 검증 55번](runtime_quality_tradeoff.md)에 기록했다.
